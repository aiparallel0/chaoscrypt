# Digest

Two files. Both state **classes of situation**, not the instances they were learned from.

| File | What it covers |
|---|---|
| [01-WORKING-METHOD.md](01-WORKING-METHOD.md) | Doing the work: verification, gates, authority, propagation, review, preserving cause |
| [02-EVIDENCE.md](02-EVIDENCE.md) | Making a claim stand up: properties versus scores, diagnosis, conservative negatives, uncertainty, scope |

## Why these exist separately from the playbook

[`../paper-pipeline/`](../paper-pipeline/) is the same experience written down while it was
happening. It is more detailed and more immediately usable — it names the venue, quotes the
correction notices, gives runnable commands. It is also bound to its instance: much of it is only
meaningful if you are preparing a conference paper for that template.

These two files are that material re-derived one level up, after the project had run long enough
to show which lessons were about papers and which were about work. Where the playbook says *"the
committee asked for terse table captions"*, this says *a requirement constrains what it names and
nothing else*.

Use the playbook to do that job. Use these to do a different one.

## The test each entry had to pass

> Would this sentence still be useful and true for a team with no papers, no venues and no
> typesetting — a group shipping a data pipeline, a compiler, a clinical model?

Where an entry could not be raised to that level, it was dropped rather than kept in weakened
form. The italic *Seen as* line under an entry is evidence that the class is real; it is not the
lesson, and nothing in it should be needed to apply the lesson.

## If you read only one thing from each

**Method:** a clean run is a statement about the process, not about the artefact. Confidence has
to come from comparing what ships against an independent authority. A check that has only ever
passed has not been tested — it has been run.

**Evidence:** passing every test a field customarily applies is not evidence of the property those
tests are believed to establish. Underneath the battery of scores there is usually one discrete
fact that decides the question, and it is worth more than all of them.

## Keeping them honest

These files will age the way the playbook did — accumulating particulars until they stop
transferring. Two habits keep that in check:

- when adding an entry, write the class first and the provenance second; if the class cannot be
  written without the provenance, it is not a class yet;
- periodically re-read for entries that have acquired a project noun, and either raise them or
  cut them.
