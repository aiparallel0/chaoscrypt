# UBMK Template Conformance

The instance-level companion to `RESEARCH-PUBLICATION-METHOD-UNIFIED.md`. That
document states the classes; this one records one venue's template with all of
its numbered requirements, the measured value that satisfies each, and the checks
that prove it.

Read it two ways. If you are preparing for this venue, it is a specification. If
you are preparing for a different one, it is a worked example of handbook
Sections 23 to 25: how ground truth is established, how a correction notice is
scoped, and what the checks have to fail on before their passes mean anything.

Every value below was measured on a rendered artifact or read out of a stored
style definition. None was copied from how the template looks.

# 1. THE AUTHORITY AND HOW TO READ IT

## 1.1 The template is a container, not a document

The venue distributes `UBMKtemplateA4.docx`. Its **appearance** is evidence of
what that file does. Its **stored style definitions** are the specification. The
committee's numbered items map one to one onto those definitions, which is the
single most useful fact about this venue.

```
unzip -o UBMKtemplateA4.docx -d tpl
tpl/word/styles.xml      <- the specification
tpl/word/numbering.xml   <- where "Fig. 1." and "TABLE I." come from
tpl/word/document.xml    <- the sample; useful, not authoritative
```

## 1.2 Word units

Every number in `styles.xml` needs converting before it means anything.

```
w:spacing before/after   twips        pt = twips / 20
w:sz, w:szCs             half-points  pt = sz / 2
w:line + lineRule="auto" 240ths       ratio = line / 240
w:line + lineRule="exact" twips       pt = line / 20   (does NOT scale)
w:ind firstLine          twips        cm = twips / 566.9
w:sz on a border         eighths-pt   pt = sz / 8
```

The `lineRule` distinction is load-bearing. An `auto` rule is a **ratio** against
single spacing and moves when the font does. An `exact` rule is an absolute
distance and ignores any global spread you set.

## 1.4 Let the target application generate the numbering

`numbering.xml` defines `TABLE %1. `, `Fig. %1.`, `%1.` for headings and `[%1]`
for references. If you produce a Word deliverable in terms of the template's own
styles, every number is generated by Word from these definitions and **cannot**
drift from the template. Typing the numbers is a second source for a quantity the
template already owns.

> **Prompt:** Unzip this template and print, for every style my document uses,
> its spacing, size, indent and numbering values converted to points and
> centimetres. Do not describe how the sample looks.

## 2.1 Item 1 was over-read, and the over-reading broke it

**Evidence:** The item says "9 punto ve italik olmali" (transliterated), meaning
9 point and italic. It was read as "italic **and not bold**" and `\bfseries` was
stripped out of the keyword line. The template's own compiled PDF sets label, dash and terms all in
`NimbusRomNo9L-MediItal`, which is 9pt **bold italic**. The submitted version had
the label bold italic and the **terms upright**, so the item was asking for the
italic the terms lacked. A property that was correct became wrong inside a fix.

The correct implementation is to change nothing about the weight:

```latex
\renewcommand{\IEEEkeywordsname}{Keywords}
\begin{IEEEkeywords}
\itshape term, term, term
\end{IEEEkeywords}
```

Stock IEEEtran supplies `\bfseries` and the italic label; the `\itshape` in the
body italicises the terms. That reproduces the template exactly.

This is handbook Section 24.1. The general form: recover the artifact as it was
when the complaint was made, and the delta between that and the requirement is
the entire ask.

## 2.2 Item 8: uppercase in the source, never \MakeUppercase

The caption is set `\scshape`. Source text that is already uppercase renders at
uniform full-cap height; Title Case renders as two-height small caps, which is
what the committee was objecting to. `\MakeUppercase` would do it too and mangles
any maths the caption carries.

## 2.3 Items 7 and 12: what leaves the caption must arrive in the body

**Evidence:** Shortening the captions moved seed counts, confidence-interval
half-widths, panel keys and a colour-map disclosure out of eleven captions. Three
facts existed **only** in a caption and were written into the body before the
caption was cut. A placeholder key-set diff confirmed `REMOVED entirely: NONE`,
and six occurrence counts fell only where the value still appeared elsewhere.

```
before cutting a caption:
  [ ] list every fact it carries
  [ ] for each, locate it in the body or ADD it there first
  [ ] re-run the float-reference check: shortening must not cost a float its
      subject-position discussion
```

# 3. THE FOUR CORRECTIONS

A second notice arrived after the fifteen items were implemented and verified. It
corrected one of the committee's own items and added three requirements.

```
C1  abstract and keywords line spacing 1, not 0.95; 0.95 starts AFTER the abstract
C2  10pt between abstract and keywords
C3  6pt after every paragraph
C4  a full stop after the table label: "TABLE I."
```

## 3.1 C1: the 0.95 starts after the keywords

```latex
\begin{abstract} ... \end{abstract}
\vspace{\dimexpr 10pt-\parskip\relax}
\begin{IEEEkeywords} \itshape ... \end{IEEEkeywords}
\linespread{0.95}\selectfont          % from here to the end of the paper
```

Measured: abstract line pitch 9.96pt in both the template and the corrected
papers, body pitch 11.40pt.

## 3.2 C2: write the gap as an expression

`\parskip` already contributes 6pt of the required 10pt. Writing `\vspace{4pt}`
would be correct today and silently wrong the moment `\parskip` moves.

```latex
\vspace{\dimexpr 10pt-\parskip\relax}
```

Measured 9.98pt. This is handbook Section 24.9.

## 3.3 C3: 6pt after every paragraph, and what it silently breaks

**Evidence:** LaTeX **adds** `\parskip` to the skip above a heading. Setting
`\parskip` to 6pt to satisfy C3 pushed the item 2 and item 3 gaps, already
verified, out of specification. The compensation is to reduce the
`\titlespacing` before-values by the same amount.

```latex
\setlength{\parskip}{6pt}
% before-values are (target - \parskip)
\titlespacing{\section}{0pt}{2pt}{4pt}       % 8pt target
\titlespacing{\subsection}{0pt}{0pt}{3pt}    % 6pt target
\titlespacing{\subsubsection}{0pt}{0pt}{2pt} % 4pt target
```

Measured after the change: paragraph gap 5.94pt, section gap 7.93pt, subsection
gap 6.02pt. All three within tolerance simultaneously.

**The reason this was not caught the first time** is that the PDF check measured
line spacing and indent but never heading or paragraph gaps. A requirement no
check covers is a requirement nobody meets.

## 3.4 C4: a full stop after the table label

The label is built by `\fnum@table` or by the caption package's label format, not
by the caption text.

```latex
\DeclareCaptionLabelFormat{ubmktable}{#1~#2.}
\captionsetup[table]{labelformat=ubmktable,labelsep=newline,
                     font={footnotesize,sc},justification=centering}
```

Renders `TABLE I.` on its own line above a centred small-caps title.

**Scope warning:** this is a UBMK rule. The stock IEEE conference template used by
other venues renders `TABLE I` with no stop, and one venue's LaTeX template
renders `TABLE I:` with a colon. Carrying this rule to another venue is handbook
handbook Section 24.5, and it has already happened once in practice.

# 4. THE AUTHOR BLOCK

## 4.1 The template's own line-by-line specification

```
line 1  author name              11pt Times upright
line 2  department               10pt Times italic
line 3  institution              10pt Times italic
line 4  city, country            10pt Times upright
line 5  e-mail address           10pt Times upright
```

```latex
\author{\IEEEauthorblockN{NAME}
\IEEEauthorblockA{\textit{Department} \\
\textit{Institution} \\
{City, Country} \\
{name@institution.edu}}}
```

## 4.2 The e-mail must carry no font command at all

**Evidence:** The papers were returned over the e-mail address. Measuring the size
and face the typesetter **asked for**, read from the page content stream rather
than from glyph bounding boxes, located it exactly:

```
line               template   measured before   verdict
name               11pt Times 10.96pt Times     ok
department         10pt ital  9.96pt ital       ok
institution        10pt ital  9.96pt ital       ok
city, country      10pt Times 9.96pt Times      ok
e-mail             10pt Times 9.96pt COURIER    wrong
```

`\texttt` had put it in Courier. At the same nominal size Courier is wider and
has a taller x-height, so it reads as the wrong typeface **and** the wrong point
size at once, which is why the notice mentioned both. Deleting `\texttt` is the
whole fix.

The template is Times throughout and defines no code style, so body identifiers
also lose their monospace:

```latex
\textit{class\_weight}=``balanced''    % not \texttt{class_weight="balanced"}
```

## 4.3 The block must actually be filled

An author block of bracketed placeholders ships as placeholder text. This is
worth a checklist line of its own because it survives every formatting check:
the spacing is right, the fonts are right, and the content is `[AUTHOR NAME]`.

```
[ ] no bracketed placeholder remains in the author block
[ ] the e-mail carries no font command
[ ] no monospaced face anywhere in the document
```

> **Prompt:** Print the requested font and point size of every line of this
> paper's author block, read from the PDF content stream, and compare each
> against the template's Author style.

# 5. THE WORD DELIVERABLE

The committee asked for the paper in Word. This is handbook Section 25.

## 5.1 Generate into the template package itself

Produce `word/document.xml` inside the template's own package, with every
paragraph carrying one of the template's style ids. The spacing, indents, fonts
and numbering then come from `word/styles.xml` and `word/numbering.xml`, not from
anything the converter asserts, and Word generates `I.`, `Fig. 1.`, `TABLE I.`
and `[1]` from the template's own counters.

## 5.2 Three items the template's styles do not carry

**Evidence:** Of the fifteen items, three were satisfied in the PDF and **not** in
the .docx, because the template's own styles contradict the committee's list.

```
item  what the style says                    what the item requires   fix
 1    Keywords basedOn Abstract (inherits b) bold italic (see 2.1)    leave inherited
 5    Abstract, Keywords: no line rule       single, per C1           leave unset
 6    Abstract firstLine 272tw, Keywords 274 288tw (0.51cm)           override to 288
13    figurecaption jc="both"                centred                  override to centre
```

Running the item checklist against the original artifact only is handbook
Section 25.5.

## 5.3 Check the .docx against its stored properties, not a rendering

0.95 line spacing is stored as 228/240 of single. Single spacing for 10pt Times
is not the same distance in Word, in LibreOffice and in LaTeX, so **one
conforming file reports three different measured values**. The style declarations
are the only fixed reference.

Two traps in reading those declarations:

```
toggle properties (b, i, smallCaps)
  properties concatenate style-first, direct-formatting-last
  read the LAST occurrence, never the first
  reading the first reports the keyword line as bold from what it INHERITS,
  ignoring the override that switches it off

a label matcher
  "TABLE [IVX]+(?![.:])" backtracks inside "TABLE III." and reports "TABLE II"
  as a label with no stop; require a numeral boundary
```

## 5.4 The converter must abort, not skip

Four defects found while building one, each of which produced a plausible-looking
document:

```
symptom                              cause
-----------------------------------  ------------------------------------------
an equation body vanished            the label was removed by splitting the body
                                     on a marker, and \label came first
C[j]=K[s(j)] rendered as X[f]=K[s(f)] the template's "equation" style sets the
                                     Symbol font, which maps Latin to Greek
paragraphs ran together              the walker never split on blank lines
a numbered environment lost its       no counter, while the body cited
number                               "Proposition 1"
```

## 5.5 Verify the conversion in both directions

```
no word absent from PDF or source   catches invention and garbling
no word dropped from source         catches loss (independent parser, no shared
                                    code with the converter)
every source number present         exact, with multiplicity
counts                              figures, tables, footnotes, references
captions present                    content words of each caption
renders within page budget          LibreOffice opens it and it is not longer
```

Two reference caveats found the hard way:

```
pdftotext is faithful for prose and LOSSY for display maths. It emitted
"P t d [j] 256" for a summation the .docx set correctly. Accept a token
explained by EITHER the PDF or the source.

small-capped headings extract as "I. I NTRODUCTION" because the small-cap glyphs
are a separate font. Accept adjacent-token joins.
```

## 6.2 What each must reject

```
check                must FAIL on                        observed
-------------------  ----------------------------------  ----------------------
float_refs           the pre-fix paper                   0 of 20 in subject
                                                         position
                     an empty file                       exit 2, "no floats
                                                         found"
ubmk_conformance     the pre-fix build (see below)       12.00pt leading,
                                                         9.90pt indent, 0.00pt
                                                         reference gap, colon
                                                         captions, Courier
                                                         e-mail
                     a document with nothing in it       exit 2, "NOTHING
                                                         MEASURED"
docx_conformance     the bare venue template             4 items fail
docx_check           a paragraph deleted                 caught
                     a number altered                    caught
                     an object removed                   caught
                     a word substituted                  caught
```

The `docx_conformance` line is the one that makes its pass meaningful: it fails
the venue's own sample document on exactly items 5, 6, 8 and 13.

**On reproducing the negative controls.** Keep them as a **commit reference**, not
as a stored file. A saved bad artifact goes missing, and the check grows past the
count you recorded next to it: the row above once read "6 of 8 fail" against a
version of the tool that had eight checks, and it now has fourteen. Build the
control instead:

```
git stash && git checkout <pre-fix-commit> -- papers/<name>/main.tex
bash scripts/compile.sh papers/<name>
python3 docs/paper-pipeline/tools/ubmk_conformance.py papers/<name>/main.pdf
git checkout HEAD -- papers/<name>/main.tex && git stash pop
```

Record **which items** fail and their measured values, never the ratio. The items
are stable; the denominator is not.

## 6.3 Two false passes worth knowing about

**Evidence, unresolved comparing equal:** The author-block font check compared two
identifiers. `/Font` is written inline inside `/Resources`, not as an indirect
reference, so a fallback that landed on the page object left the font map empty
and every name resolved to `?`. `? == ?` certified Courier as matching Times, and
the check passed on the artifact that had already been rejected.

**Evidence, a pattern that never fires:** A search for monospaced faces used
`/Mono/`. The font present was `NimbusMonL`, with no trailing letter, and
`pdffonts` prints every name behind a six-character subset tag. The search
returned empty and the document was declared clean.

Both are handbook Sections 23.2 and 23.3.

## 6.4 The build gate

```
[ ] exit status tested in BOTH directions
[ ] prior outputs deleted before the build, so existence proves this run
[ ] LaTeX errors, overfull boxes, undefined references, page limit
[ ] MISSING CHARACTER warnings promoted to failures
[ ] unfilled placeholders are fatal, not marked
[ ] main.pdf left untouched when the gate refuses
```

**Evidence, the last two:** A build script returned exit 1 on a passing 6-page
build and exit 0 on a failing 7-page one, and proved success by the PDF merely
existing, so a stale artifact survived a fatal error. Separately, an unfilled
placeholder whose key contained an underscore threw a text-mode error whose
recovery **silently swallowed a figure, a table and the section numbering**, in a
document that still compiled to the correct page count. A visible `[?key]` marker
cannot help, because it is only visible if the document still typesets.

**Evidence, missing characters:** A glyph the font lacks is dropped with nothing
but a log line. The page builds, no box overflows, nothing is undefined, and an
identifier quietly loses a character.

# 7. THE SUBMISSION PACKAGE

```
[ ] the filled source ships as main.tex, with no placeholder step to run
[ ] only the figures the source actually references
[ ] the .bbl included, so BibTeX is not required
[ ] built in a THROWAWAY directory before it is sealed
[ ] the PDF the package produces is put through the same conformance check as
    the one built locally
[ ] page count, float count and error counts recorded from the clean-room build
```

The last two are the ones that are skipped. A package that builds is not the same
claim as a package that builds **the same thing**.

Observed on both papers: 6 pages, 11 floats, 0 errors, 0 overfull, 0 undefined,
and the clean-room PDF passing conformance.

# 8. WHERE THE TEMPLATE CONTRADICTS ITSELF

Measured, not inferred. Useful because it tells you which authority to follow and
what to say when you do.

```
point                     the .docx template says     the committee's list says
------------------------  --------------------------  -------------------------
keywords weight           sample sets b=0 explicitly  see 2.1; the LaTeX
                                                      template renders bold
abstract line spacing     no line rule set            single, per C1 (agrees)
abstract indent           272tw                       288tw (item 6)
figure caption alignment  jc="both"                   centred (item 13)
table title case          sample is Title Case        full capitals (item 8)
```

Measured against the committee's own fifteen items, the template's sample
document **fails items 5, 6, 8 and 13**.

```
resolution used:
  the numbered list is the later and more specific instruction, so it wins
  the disagreement is recorded in the source comments
  the reply to the committee states which was followed, in one sentence
```

The third line is what protects you. Silent choice is the defect, not the choice.

```

[ ] numbering.xml read: which counters the target application generates
[ ] the committee's items mapped onto style names
```

## 9.2 Before sending a revision

```
[ ] every numbered item measured on the RENDERED artifact
[ ] heading and paragraph gaps measured, not assumed
[ ] author block filled, no bracketed placeholder
[ ] no monospaced face anywhere
[ ] float-reference check prints NONE
[ ] page limit held, 0 overfull, 0 undefined, 0 missing characters
[ ] every check re-validated against the artifact it must reject
[ ] the second-format artifact put through the same item list
[ ] clean-room package build passes conformance
[ ] the reply says which authority was followed where they disagreed
```

## 9.3 When a correction notice arrives

```
[ ] recover the artifact as it was when the notice was written
[ ] compute the delta per item; that delta is the entire ask
[ ] anything outside the delta needs its own justification
[ ] search for OTHER instances of each rule, not just the flagged one
[ ] after any global parameter change, re-measure every dependent item
[ ] check whether the notice corrects an earlier notice
```

## 10.2 Scope a correction notice

```
Here is a correction notice and the artifact as it was when the notice was
written.

```

```
Then run the same item list against the second-format deliverable, reading its
stored properties rather than a rendering.
```
